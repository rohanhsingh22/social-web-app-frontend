# Motion

## 1. Purpose

This document defines motion and animation principles for the HiRotoli frontend.

Motion should make the interface feel:

- Natural
- Responsive
- Calm
- Modern
- Human
- Connected

Motion must support usability rather than distract from the experience.

HiRotoli is a social application, so motion should communicate:

- Interaction
- Connection
- Presence
- Navigation
- State changes
- Feedback
- Spatial relationships

Motion must never become the product itself.

---

# 2. Motion Principles

HiRotoli follows these principles:

1. Motion must have a purpose.
2. Keep animations short and subtle.
3. Prefer natural movement over exaggerated effects.
4. Use motion to explain state changes.
5. Use consistent timing across the application.
6. Avoid unnecessary animation.
7. Respect reduced-motion preferences.
8. Never block important interactions because of animation.
9. Avoid continuous decorative movement.
10. Prefer opacity and transform animations over layout animations.
11. Motion should feel consistent across desktop and mobile.
12. Shared components should use shared motion rules.
13. Do not introduce animation libraries for isolated visual effects without approval.
14. Motion should reinforce HiRotoli's human and social identity.
